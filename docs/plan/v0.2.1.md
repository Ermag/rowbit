# v0.2.1 plan

v0.2.1 makes trying Rowbit take two commands and no Rust, and makes it easy to tell what Rowbit is from the repository or the home page within a screen. It ships as the tag `v0.2.1` with a GitHub Release holding the binaries. The public announcement follows it; per-agent budgets are still v0.3.

```sh
curl -fsSL https://ermag.github.io/rowbit/install.sh | sh
rowbit demo
```

`rowbit demo` starts the shop database and the review page, offers to connect an agent client it finds (Claude Code, Cursor, VS Code, Claude Desktop, Codex, Gemini CLI or Windsurf), and prints the sentence to ask the agent. The agent proposes a write, Rowbit holds it, and the agent hands back a link to the change on the review page.

The behaviour is specified in [docs/spec/setup.md](../spec/setup.md) (the release, the install script, `rowbit demo`, `rowbit connect`, the skill, the home page and the docs site) and, for the review link agents get back, the [change lifecycle](../spec/change-lifecycle.md#agent-tools-mcp). `rowbit.yml`, `rowbit-server.yml` and the state file don't change.

It draws on a look at how uv, Ollama, Context7, Playwright MCP, GitHub's MCP server, Supabase MCP and Neon present themselves and set up agents, and at how each agent client installs an MCP server today.

## Choices made in the spec

- **Two commands, one terminal.** `rowbit demo` connects an agent itself, offering the clients it finds, as Context7's and Neon's setup commands do. One client per demo, because an agent has one token; `rowbit connect --new-token` moves it to another. `rowbit connect` is the same code, for later and for real deployments.
- **Tell people what to ask.** The first success is the agent's write being held, so the demo prints a prompt chosen to produce the too-broad `UPDATE`, checked with each client in the Sam pass.
- **Held results carry a link.** Without one, the agent says "held" and the person doesn't know where to look. The link holds nothing secret: the page still needs sign-in, and the agent could already reach it.
- **No Windows build.** Rowbit makes `rowbit.db`, which holds copies of changed rows, readable by its owner only, and does that with Unix permissions. Windows users can run the Linux build under WSL.
- **Static Linux builds.** `musl` binaries run on any distribution without a matching glibc; native `arm64` runners build `aarch64` without cross-compiling C.
- **The install script installs to `~/.local/bin` without `sudo`,** and checks the archive against `SHA256SUMS`. That catches a broken download, not a compromised release; `gh attestation verify` checks provenance, and the docs say how.
- **The release publishes itself.** Pushing the tag is the decision to release; the workflow publishes only after every build, checksum and attestation succeeded.
- **The demo needs Docker.** Preview replays writes inside MariaDB or MySQL, so there is no demo without a real server.
- **The demo is HTTP from the start.** Its `rowbit-server.yml` turns on `mcp.http`, so agents get a token, never the database URL or the state file.
- **`rowbit connect` uses each client's own command where it has one** (`claude mcp add`, `code --add-mcp`, `gemini mcp add`) and edits the file where it doesn't, or where the command can't set a header (Cursor, Windsurf, Claude Desktop, Codex), keeping a backup and refusing files it can't parse.
- **Install buttons are the second path.** A link can't carry a per-agent token, so the VS Code and Cursor buttons point at the local `/mcp` and ask for the token; they're labelled for after `rowbit demo`, below `rowbit connect`.
- **Agent tokens stay on the CLI.** The web UI doesn't hand out agent credentials in v0.2.1.
- **Docs come from `docs/`.** The repository stays the one source; the site renders it, so GitHub and the site never disagree. mdBook keeps Node out of the docs build.
- **Agents may set up the demo, people set up the real thing.** The home page offers a prompt that has an agent install Rowbit and start the demo. The docs say that for a real database a person sets Rowbit up, since the agent mustn't hold the database credentials or edit its own rules.

## Decided with Philip

- **The MCP Registry** waits for v0.2.2. It lists only npm, PyPI, NuGet, container images, `.mcpb` bundles and remote URLs, not a binary on GitHub Releases, so the listing comes with a `ghcr.io/ermag/rowbit` image or a bundle.
- **macOS binaries ship unsigned.** Binaries downloaded with `curl` aren't quarantined, so the install script's binary runs as is. A `.tar.gz` downloaded in a browser is, and the docs give the `xattr -d com.apple.quarantine rowbit` step. Signing needs an Apple Developer Program membership; revisit if people hit it.
- **No Homebrew tap yet.** It needs a second repository (`Ermag/homebrew-rowbit`) and a formula bump each release; add it if people ask.
- **The install URL stays on `ermag.github.io/rowbit`.**
