# v0.2.1 plan

v0.2.1 makes trying Rowbit take three commands and no Rust: install a prebuilt binary, start a demo, connect an agent. It ships as the tag `v0.2.1` with a GitHub Release holding the binaries. The public announcement follows it; per-agent budgets are still v0.3.

```sh
curl -fsSL https://ermag.github.io/rowbit/install.sh | sh
rowbit demo
rowbit connect claude-code      # in another terminal, inside rowbit-demo/
```

The behaviour is specified in [docs/spec/setup.md](../spec/setup.md): the release and the install script, `rowbit demo`, and `rowbit connect`. Nothing in the change lifecycle, `rowbit.yml` or `rowbit-server.yml` changes, and the state file gains nothing.

## Choices made in the spec

- **No Windows build.** Rowbit makes `rowbit.db`, which holds copies of changed rows, readable by its owner only, and does that with Unix permissions. Windows users can run the Linux build under WSL.
- **Static Linux builds.** `musl` binaries run on any distribution without a matching glibc; native `arm64` runners build `aarch64` without cross-compiling C.
- **The install script installs to `~/.local/bin` without `sudo`,** and checks the archive against `SHA256SUMS`. That catches a broken download, not a compromised release; `gh attestation verify` checks provenance, and the docs say how.
- **The release publishes itself.** Pushing the tag is the decision to release; the workflow publishes only after every build, checksum and attestation succeeded, so a half-made release is never public.
- **The demo needs Docker.** Preview replays writes inside MariaDB or MySQL, so there is no demo without a real server. `rowbit demo` drives `docker compose` with the quickstart's own files rather than shipping its own database.
- **The demo is HTTP from the start.** Its `rowbit-server.yml` turns on `mcp.http`, so `rowbit connect` hands the agent a token, never the database URL or the state file.
- **Agent tokens stay on the CLI.** `rowbit connect` makes them the way `rowbit agents token` does, as whoever can write the state file. The web UI doesn't hand out agent credentials in v0.2.1; a "connect an agent" page with install links can come once the CLI path has been used.
- **`rowbit connect` uses each client's own command where it has one** (`claude mcp add`, `code --add-mcp`) and edits a JSON file only where it doesn't (Cursor, Claude Desktop), keeping a backup and refusing files it can't parse. Four clients (Claude Code, VS Code, Cursor, Claude Desktop); `--print` covers the rest, Codex included, until its HTTP setup settles.

## Open for Philip

- **macOS signing and notarization.** Binaries downloaded with `curl` aren't quarantined, so the install script's binary runs as is. A `.tar.gz` downloaded in a browser is, and macOS refuses to run it until `xattr -d com.apple.quarantine rowbit`. Signing and notarizing needs an Apple Developer Program membership ($99 a year) and its certificate as a repository secret. The plan ships unsigned and documents the `xattr` step.
- **Homebrew and a container image** are left out of v0.2.1. A tap needs a second repository (`Ermag/homebrew-rowbit`); an image on `ghcr.io` matters more for running `rowbit serve` for a team than for trying Rowbit.
