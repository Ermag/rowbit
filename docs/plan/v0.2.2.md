# v0.2.2 plan

v0.2.2 makes the first run on your own database as easy as the demo, and fixes the demo leaving the agent unconnected. It ships as the tag `v0.2.2` with a GitHub Release holding the binaries, plus a container image and an MCP Registry listing. The public announcement waits until the first-time experience is right; named connections (prod, test, dev in one Rowbit) and per-agent budgets are v0.3.

```sh
curl -fsSL https://ermag.github.io/rowbit/install.sh | sh
rowbit setup
```

`rowbit setup` asks first whether to use your own database or a sample one. The sample path runs today's demo. Your own database gets a connection and privilege check, a starter `rowbit.yml` that holds every write, the agent clients it finds (preselected), the skill, the review page's password, and how to keep Rowbit running.

## What v0.2.1 got wrong

- **The demo connects Claude Code in one directory and the quickstart sends you to another.** `rowbit demo` adds Rowbit at Claude Code's local scope for `rowbit-demo/workspace`, while the quickstart's first instruction after starting it is `cd rowbit-demo`. Claude Code started there has no Rowbit tools; in Philip's run it found Rowbit's database login in the demo's files instead, and stopped.
- **Nothing sets Rowbit up on your own database.** The quickstart is the demo; the path to a real database is "copy these files and edit them".
- **Nothing says which databases work,** or that agents read through Rowbit too.

## Choices

- **The demo stays, inside setup.** Someone trying Rowbit often has no database they'll point a new tool at; the sample shows a held change in two minutes. `rowbit demo` stays a command of its own for scripts and CI.
- **The agent's workspace stays separate from the demo's files.** It keeps the database login, `rowbit.db` and the page password out of the folder the agent works in; the fix is making the directory impossible to miss, not removing it.
- **Setup spends its questions on the database, not the machine.** The OS only changes PATH hints and the service file. The privilege check and a policy that holds everything are what keep a first real run safe.
- **Setup's files live outside your projects.** An agent working in a project folder shouldn't find Rowbit's database URL there. Other commands look in the current directory first, as today, then in `~/.rowbit/default`.
- **Setup writes config in the shape named connections will use,** with its one connection called `default`, so v0.3 needs no migration.

## Decided with Philip

- **v0.2.2 is "Set up on your database";** the container image and MCP Registry listing stay in it.
- **The announcement waits** until Philip is satisfied with the first-time experience, not for a fixed release.
- **Named connections are v0.3,** ahead of budgets. An agent reaches no connection unless `rowbit.yml` names it for that agent.
- **The support table lists NoSQL databases** as examples of what's being explored, MongoDB and Redis among them.
