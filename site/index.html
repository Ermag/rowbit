ROWBIT

A safety net for AI agents that write to your database. Preview every write, let a person approve the risky ones, undo any single change.

v0.2.1MCP server for MariaDB & MySQLOpen source, AGPL-3.0GitHub

TRY IT: TWO COMMANDS

Installs rowbit, then runs a sample shop database in Docker with Rowbit in front of it, connects your agent and opens the review page. macOS and Linux (Windows through WSL); the demo needs Docker. Read install.sh before you run it.

1
curl -fsSL https://ermag.github.io/rowbit/install.sh | sh
2
rowbit demo

Then ask your agent: Some orders are stuck in pending. Cancel them. Its write matches orders placed minutes ago too, so Rowbit holds it, and the agent hands you a link to review all 1,284 rows.

PRESS START

A simulation, not the real UI. A coding agent gets a vague task and writes an update that's far too broad. Step through what Rowbit does with it; you play the person reviewing.

    AGENT // coding-agent
    ROWBIT // reviewshop @ MariaDB 11.4
    Step 1 of 7

    AUDIT LOG

    Every write an agent proposes is logged with who asked, what the rules decided, who approved it and what it changed, in a hash chain. Any applied change can be undone on its own, without restoring a backup.

    CHANGES // todayagent identity from its MCP token

    HOW IT WORKS

    Agents talk to Rowbit over MCP, never to the database. Rowbit holds the database credentials.

    MCP SERVER

    Agents get four tools: read, see the schema, propose a write, follow it. None of them approves. Over HTTP each agent has a token of its own.

    EXACT PREVIEW

    Rowbit reads the rows a write would change and replays it on a private temporary copy, so you see each row before and after. Your tables are only read.

    RULES + PEOPLE

    A small YAML file lets safe writes through, holds risky ones for a person, and refuses the rest. Approval applies exactly what was previewed, or nothing.

    UNDO ONE CHANGE

    Before-images are kept per change, so you can take back one bad write and keep everything else. Undo refuses if someone changed those rows since.

    SCOPES

    Per agent, which tables it may read or write and which columns it may never see, compiled into grants on a database user of its own.

    SHADOW MODE

    Put an agent behind Rowbit without slowing it down, see what the rules would have held, and replay real traffic against new rules.

    REVIEW ANYWHERE

    A web UI built into the binary, sign-in through your identity provider, and Slack or webhook notifications when a write is held.

    AUDIT LOG

    Who asked, what the rules said, who approved and what changed, for every write, in a hash chain rowbit verify checks.
